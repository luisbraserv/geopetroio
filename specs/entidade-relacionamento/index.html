Modelo de dados GeopetroIO

Todas as estruturas persistentes do projeto num só lugar: os databases MySQL do Braserv-Core e do Geopetro-Backend, a série de telemetria no InfluxDB e o armazenamento local dos dois desktops. Linha cheia é chave estrangeira declarada no mesmo banco. Linha tracejada é vínculo entre serviços ou mantido apenas pelo código.

Vínculos sem chave estrangeira

  • [FATO] unidades.nome é o idUnidade dos tópicos MQTT e da measurement telemetria (RN-018). Renomear uma unidade separa o histórico dela no InfluxDB.
  • [FATO 2026-10-06] As colunas unidade_id do Geopetro-Backend referenciam braserv_core.unidades.id, mas não possuem FK entre databases. A exclusão é protegida pela consulta /internal/v1/unidades/{id}/vinculos.
  • [FATO] evento_alarme.episodio_id e episodio_alarme_extremo.episodio_id identificam o mesmo episódio. Não há FK entre as duas tabelas; o extremo é semeado a partir do log em V2026.09.09.2 e depois atualizado pelo serviço.
  • [FATO] criado_por e atualizado_por guardam o username de quem gravou, como texto e sem FK para usuarios. Conferido nos serviços de cenários, cards e limites.
  • [FATO] As colunas de leitura_local no Geopetro-Desktop coincidem com as tags e fields do ponto gravado no InfluxDB. As leituras chegam ao servidor pelo tópico telemetria/{idUnidade}/batch.
  • [FATO] usuarios.empresa (texto) convive com usuarios.empresa_id (FK para empresas). [INFERÊNCIA] O texto é resquício de antes do cadastro de empresas.

Fora do diagrama

  • flyway_schema_history: controle de versão do Flyway no MySQL. Não é dado de negócio.
  • Geopetro-Front: o simulador guarda estado, relatórios e aditivos no localStorage do navegador. Nada disso chega ao servidor sem o usuário salvar o cenário.
  • Geopetro-Desktop: config/app-settings.json e os snapshots locais guardam configuração da estação, não leituras.
  • Braserv-Horus-Desktop: H2DatabaseService cria uma tabela H2 registro_operacao, mas nenhuma outra classe usa esse serviço. O application.properties declara um datasource MySQL (braservone) sem nenhuma entidade mapeada.

Como manter

O diagrama e o dicionário saem das constantes TABELAS e RELACOES no início do script deste arquivo. A cada migration em apps/core/app/src/main/resources/db/migration ou apps/geopetro-backend/app/src/main/resources/db/migration, ajuste as colunas aqui no mesmo commit. Tabela nova precisa de uma posição x/y livre no diagrama; as linhas são desenhadas a partir da posição de cada coluna.
